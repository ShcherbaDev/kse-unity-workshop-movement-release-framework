## 2026-10-03 - Core: state machine, motor, sensor (feat/core)

- **Tool:** Claude Code (Claude Opus 5.5)
- **Design (by architect, before generation):** One state machine shared by player and enemies. No central transition table: each state declares `Priority`, `CanEnter()` (re-checked while active) and `CanExit()` (blocks switching, e.g. an unfinished dash). The highest-priority enterable state wins, ties go to the first listed, the current state stays if nothing can enter. States are MonoBehaviour components (`ComponentState`) so adding a mechanic = Add Component, with Inspector config for free. `PlatformerMotor2D` is the only thing that writes Rigidbody2D velocity. `StateController` refreshes `EnvironmentSensor2D` explicitly before ticking states (no script execution order changes). Review changes: renamed `Approach` -> `AccelerateTowards`, `Probe` -> `CastForSurface` for readability; kept states as MonoBehaviour components (rejected plain `[SerializeReference]` classes: no built-in type picker, renaming a class loses data).
- **Prompt:** Implement the above plus: motor `MoveHorizontal(target, accel, decel, dt)` (accelerate only when speeding up in the same direction, otherwise decelerate), `Jump(height)` from `v = sqrt(2gh)`, gravity multiplier relative to the startup gravity scale, fall speed clamp. Sensor: casts via `Rigidbody2D.Cast` (ignores own colliders), slope limit splits ground vs wall normals, grounded only when not moving away from the ground normal (handles jump start and one-way platforms), ledge raycast past the collider edge, gizmos. XML docs on public API.

## 2026-10-04 - Player state system (feat/player)

- **Tool:** Claude Code (Claude Opus 5.5)
- **Design (by architect):** Minimal player layer the spec expects ("Ground/Air/Wall states", Move and Jump done so teammates add new mechanics). `PlayerState` exposes Motor/Sensor/InputReader via lazy lookups (subclass `Awake` cannot break them). Input read by action name so new mechanics need no package changes.
- **Prompt:** `PlayerInputReader` (timestamped presses with buffer, `WasPressed(name, buffer)`, `ConsumePress`, `IsHeld`, digital `Horizontal`/`Vertical`, project-wide actions fallback), `PlayerController`, `GroundState`, `AirState` (air control, fall gravity, jump-release gravity for variable height, max fall speed), `JumpState` (priority 10, jump buffer, coyote time that cannot grant a second jump).
- **Bug found by tests:** priority set in `ComponentState.Reset()` is skipped for components added from code, so `JumpState` lost ties to `GroundState`. Fixed by making `Priority` a code-defined virtual property.
- **Review changes:** input switched from string map/action names to `InputActionReference` fields (architect's call: no strings; a generated actions class cannot be used because package code cannot reference the game's Assembly-CSharp, and a package-owned actions asset would be read-only for teammates). Presses are recorded via `InputSystem.onActionChange`, so any button can be buffered without registering it. Tests assign references via reflection to avoid test-only public setters. Removed digital Horizontal/Vertical conversion: deadzones and keyboard diagonals belong in the actions asset (composite Mode = Digital), states read raw `Move.x` (analog stick = analog speed). Gravity scale default removed (left to library users); slope support removed (no slopes in the game): sensor uses vertical velocity instead of ground normal.

## 2026-10-04 - Enemy state system (feat/enemy)

- **Tool:** Claude Code (Claude Opus 5.5)
- **Design (by architect):** Mirror the player layer: `EnemyController : StateController<EnemyState>`, states as components. No `BaseEnemy` subclass hierarchy: an enemy type ("JumpEnemy") is a prefab = controller + states. Target found by layer (`TargetSensor2D`) instead of a scene reference, so prefabs stay scene-independent. Only Patrol is provided; chase/jump/charge states are left to teammates. Review change: renamed `EnemyBehaviour`/`PatrolBehaviour` to `EnemyState`/`PatrolState`: same state machine as the player, so one name for one concept (and `Behaviour` clashes with `UnityEngine.Behaviour`).
- **Prompt:** `EnemyController`, `EnemyState` (lazy Motor/Sensor/TargetSensor), `TargetSensor2D.FindTarget()` via OverlapCircle + gizmo, `PatrolState` (always enterable fallback, turns at walls/ledges, stops instantly on turn so momentum cannot carry it off a ledge, stands still if both sides are blocked to avoid jitter on tiny platforms).
- **Verification:** PlayMode tests: turns at a ledge and stays on the platform, turns at a wall, stands still on a platform as wide as itself. Mutation check: with blocking disabled all three fail with the expected messages. PlayMode 10/10.

## 2026-10-13 - Animation layer (feat/animation)

- **Tool:** Claude Code (Claude Opus 5.5)
- **Design (by architect, before generation):** The gameplay state machine stays the single source of truth; the Animator only displays it. Each state names its Animator state in the Inspector and `CharacterAnimator` plays it instantly with `Animator.Play` (sprite sheets cannot cross-fade), so the Animator graph has no transitions; `Speed`/`VerticalSpeed`/`Grounded` feed blend trees. Reactions and actions end with their clip (`IsAnimationFinished`), which can never leave a state stuck. Animation Events reach only the active state whose animation fired them, plus a C# event for VFX and sound. No breaking changes: Hurt/Death are written per character type instead of a shared base class for player and enemy states (that would change `CurrentState`); states with `CanExit() == false` are not interrupted, as in 0.1.0.
- **Prompt:** CharacterAnimator on the character root - plays the active state's Animator state by name with Animator.Play (no cross-fade), writes Speed/VerticalSpeed/Grounded if the controller has them. ComponentState.AnimationState set in the Inspector, IsAnimationFinished for states that end with their clip, Animation Events through a relay to the active state and a C# event. `StateController` passes every new state to CharacterAnimator. No breaking changes to 0.1.0.
- **Details settled before implementation:** no restart is decided from the previous gameplay state and the last played animation, not from `AnimatorStateInfo`, which can be stale; `Animator.Update(0f)` right after `Play`, so the state info is fresh at once; `Trigger()` is ignored while Hurt is active (clearing the flag in `Exit` would make the state enter again forever); Animator activity and controller are checked before `HasState`.
- **Changes:** `CharacterAnimator` (playback, parameters, `IsAnimationFinished`, event routing; plays the active animation again whenever the Animator leaves it: re-enable, pooling, `Rebind`, a swapped controller, whose parameters are looked up again); `AnimationEventRelay` (receives clip events on the Animator's GameObject); `ComponentState.AnimationState`, `IsAnimationFinished`, `OnAnimationEvent`; `StateController` passes every new state to `CharacterAnimator`. Adding `CharacterAnimator` fills in the Animator (inactive children included) and adds the relay through Undo. Demo sample animated with generated rectangle clips: locomotion, air, Hurt on H, patrolling enemy. README Animation section, CHANGELOG 0.2.0.
- **Simplification:** sprite-sheet animation only, so the Animator graph must have no transitions. That replaced the disable tracking (relay `OnDisable`, polling the Animator's activity, `keepAnimatorStateOnDisable` check) with one check in `Update` and also covers `Animator.Rebind()`. Tests kept to the core rules (26 -> 13): cases that run the same code path or only cover a trivial guard were removed. README Animation section shortened: Death described in one sentence, the Cast example merged into Animation Events.
- **Verification:** PlayMode 22/22 (10 existing + 12 animation), EditMode 14/14 (1 animation). Each bug fix had a test that failed first, e.g. stale state info without `Update(0f)`, the event filter for a state whose animation is not playing, the controller swap, `Rebind`. Demo checked in Play mode: Locomotion with the idle breathing, the Hurt flash returns to Locomotion with the body color restored, enemies bob and flip while patrolling, clean console. README examples compile in the dev project.

## 2026-10-28 - Interrupts and obstacle layers (fix/interrupts-and-obstacles)

- **Tool:** Claude Code (Claude Opus 5.5)
- **Prompt:** Review the bugs (QA list for the game repo), decide which belong to the framework.
- **Framework bug:** Death cannot interrupt Hurt (`StateMachine` skipped selection entirely while `CanExit()` was false), blind charge runs in place against another enemy and its run animation keeps playing (wall checks see only Ground layers while characters still collide).
- **Design (by architect):** opt-in interrupts instead of "higher priority always wins", so dash, blind chase and enemy jumps already in the game are never cut off unless a state asks for it. `CanInterrupt` is a default interface member, so `IState` implementers compile unchanged. When the current state is locked, non-interrupters are skipped before `CanEnter()`, so without opt-in the machine makes exactly the same calls as 0.2.0. Obstacle Layers default to empty and affect wall checks only.
- **Changes:** `IState.CanInterrupt`, `ComponentState.CanInterrupt`, `StateMachine.Select` lock filter, `EnvironmentSensor2D._obstacleLayers`, demo `PlayerHurtState` opts in, README (priorities, Hurt/Death, setup step 3, limitations), CHANGELOG 0.3.0.
- **Verification:** new tests failed first (interrupt replaces a locked state; the obstacle box is a wall only when listed); mutation check: wall mask without obstacles fails the sensor test. EditMode 16/16, PlayMode 23/23.
